# S3 验收清单（实现 agent 提议，审核 agent 可改）

> S3 = 检索层（PRD 第 9 章）：多语种召回、术语映射、合规时效过滤、引用装配、库版本留痕。
> 验证：`python scripts/verify_s3.py`（SQLite）/ `python scripts/verify_s3.py --dsn <DSN>`（PostgreSQL）。

## 0. 口径声明（先看这条）

本轮实现的是 **多语种词法检索（BM25）+ 结构化精确匹配 + RRF 融合**，
**不是向量语义检索**。`Embedder` 接口与 `NullEmbedder` 占位已就绪，S4 接 BGE-M3 + pgvector。
因此本轮**只能证明"检索管线与合规时效可用"**，不能宣称语义召回能力（PRD 9.5 两层评测口径）。

## 一、必过条款

| # | 条款 | PRD 出处 | 验证方式 |
| --- | --- | --- | --- |
| 1.1 | 知识块必须有**可回指标识**（证书号/条款号/型号/条目 ID） | FR-KB-07、PRD 9.3 | 每块 identifiers 非空；草稿每条引用都能在库里查到 |
| 1.2 | 知识块必须带**时效字段**（生效/废止/有效期） | PRD 9.4 难点② | 过期证书、已废止证书、未生效条款各一条用例 |
| 1.3 | **过期内容不得进入结果、更不得被引用** | PRD 9.4 难点②、FR-KB-05 | TC-M77-118（2026-08-12 过期）、CERT-CE-1890（已废止）不出现 |
| 1.4 | **未生效条款可见但不得作为当前要求输出** | PRD 9.4 难点② | REG-US-204 标记 `not_yet_effective=true`，且不进草稿引用 |
| 1.5 | 跨语种召回：es/ar/zh/en 提问命中中文产品库 | PRD 9.4 难点① | 四语各一条用例 |
| 1.6 | 术语表映射：多语说法 → 标准概念 | PRD 9.2 | 5 条用例（含阿语定冠词） |
| 1.7 | 结构化通道优先：点名型号 → 该型号第一 | PRD 9.3 | M-77 用例 |
| 1.8 | 目的国过滤：法规按买家国别 | PRD 9.4 难点② | BR 买家命中 REG-BR-077，不命中 REG-AE-099 |
| 1.9 | 草稿数据**来自知识库**（不是写死常量） | FR-KB-03 | 改库里的价格 → 草稿价格随之变化 |
| 1.10 | 引用带库版本留痕 | PRD 11.4 | 每条引用 note 含「库版本 kb-…」 |
| 1.11 | 命中不重复 | — | 同一块在多个通道命中只出现一次 |
| 1.12 | 双后端一致 | PRD 9.5 | SQLite / PostgreSQL 各跑一遍 |

## 二、已知不足（实现 agent 自己先说）

| # | 不足 | 影响 | 计划 |
| --- | --- | --- | --- |
| L1 | 词法检索对**同义改写**不敏感（问"多久能发货"未必命中"交期"） | 召回率受限 | S4 用向量 + 查询扩展补 |
| L2 | 多语种知识块正文四语并列，词法区分度有限 | 排序可能不理想 | S4 向量 + 结构化加权 |
| L3 | 检索在应用进程内做（块量小时够用） | 大规模下需下推到向量库 | S4 pgvector |
| L4 | 知识库靠启动时灌种子 | 无版本化发布流程 | 按 PRD 13.4.8 做发布流水线 |
| L5 | 公开检索基准（MIRACL/MLDR/…）**尚未接入** | 无法给出基准体检数据 | S4 接入 |

## 三、审核方建议重点看

1. **时效过滤有没有漏网**（尤其结构化通道 —— 早期版本就是从这条通道把过期证书"复活"的）
2. **引用与草稿正文是否一致**（草稿说 25-30 天，引用块是不是真的写着 25-30 天）
3. **改库 → 草稿变化**这条是否真的成立（会不会只是模板里写死了价格）
4. **未生效条款**是否被当成"当前要求"输出给了买家
