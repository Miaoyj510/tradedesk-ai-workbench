| # | 条款 | 判据 |
| --- | --- | --- |
| D1 | PRD 12.4 | 成本看板的**单位成本分母是询盘条数**，不是调用次数（一条询盘 3 次调用、0.02 元 → 单位成本 0.02） |

## 三、本轮（R21）修掉的根因

| 根因 | 优先级 | 一句话 |
| --- | --- | --- |
| R21-01 | **P1 安全** | 事件流文本与草稿正文不转义 → 存储型 XSS |
| R21-02 | P1 | 名单命中面板写死条目 ID → 与证据链说的不是一条 |
| R21-03 | P1 | 看板顶栏与门槛卡片全是写死的 mock 数字，还宣称"已达标" |
| R21-04 | P1 | mock 固定译文挂在真买家消息下面 |
| R21-05 | P1 口径 | "元/条询盘"算的是"元/次调用" → 把 PRD 12.4 硬指标报错了 |
| R21-06 / R21-07 | P2 | `draftReady` 口径错；`sent` 变量遮蔽返回 `null` |
| R21-08 | P2 | 预算常量无出处，与硬指标差 12 倍口径 |
| R21-09 / R21-10 | P2 | 空表无说明、`notes` 未渲染；库版本写死且是错的 |
| R21-11 | P2 | FR-ORC-10 第 4 类筛选没做 |
| R21-12 | P3 | 跨地址调试承诺不可用、缺验收基线、跨天时间戳 |

> **这轮最值得记的不是缺陷，是自证的盲区**：`verify_s6_ui.js` 只跑了 `api.js`（数据层），
> `app.js` 怎么把数据画成界面**一次都没被跑过** ——
> 于是"数据对、界面说错"这一类问题一个都没被发现。
> **"接上真数据" ≠ "界面显示的是真数据"。**
