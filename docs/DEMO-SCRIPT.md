# 3 分钟演示脚本（面试 / 评审现场用）

> 目标：**3 分钟内让对方看懂三件事** —— 这是真产品（不是原型截图）、它守住了人在环的确定性、
> 以及它被独立审核证伪过（不是自说自话）。
> 配套：`docs/PORTFOLIO.md`（一页纸）、`docs/ARCHITECTURE.md`（架构图）。

---

## 0. 演示前 3 分钟准备

```powershell
& ".\dev.ps1" up        # PostgreSQL + Redis（Docker）
& ".\dev.ps1" serve     # 后端 + 前端（http://127.0.0.1:8080/ui/）
```

- 浏览器打开 `http://127.0.0.1:8080/ui/`，用 **sales / demo1234** 登录（演示账号页上直接可点）。
- 确认左侧"询盘工作台"有 ≥ 1 条待签核线程；没有就现场发一条（30 秒）：
  ```powershell
  curl -s -X POST http://127.0.0.1:8080/inbound -H "Content-Type: application/json" `
    -d '{"buyer_id":"BY-DEMO","message":"Hi, could you quote 500 pcs of X-200 FOB Shenzhen? Do you have CE certification?","language":"en","company":"Northwind Trading LLC","country":"US"}'
  ```
- 另备一个终端窗口（现场跑硬证据，见第 5 节）。

## 1. 时间轴

### 0:00–0:25 · 一句话定位 + 痛点

**说**：
> "这是给中小外贸团队的 AI 数字员工工作台。外贸业务员的日常是五件事：询盘应答、客户背调、
> 交易风控（Sentinel）做成 Agent，商品运营（Merch）、推广（Growth）本期只做角色声明；
> 业务员只做价格谈判和合同确认。
> 我做的是其中三条——询盘应答、交易风控、调度器与线程状态机，今天讲的是**产品机制可验证**的版本。"

**不要说**：不要讲模型选型、不要讲"用了 RAG 所以很先进"。

---

### 0:25–1:10 · 询盘工作台：人在环的确定性（核心画面）

**点**：左侧「询盘工作台」→ 选那条**阿语**询盘。

**说**：
> "这是一条真实的阿语询盘。Inquiry 生成的是**草稿**，不是回复——
> 右上角这 11 条是闸门：价格承诺 GATE-01 和认证声明 GATE-05 亮红，等人工签核；
> 名单命中 GATE-03 是绿的，说明这条没命中制裁名单。中间是草稿正文，
> 下面这一排标签是**引用**：SPEC-X-200 是规格记录、SKU-X-200-ar 是阿语产品条目、
> CERT-CE-2041 是证书编号——每一条都能回指到知识库的具体条目。"

**再点**：切到英语 / 西语那两条。

**说**：
> "同一个工作台，三种语言。草稿里的价格 4.85–5.2、交期 25–30 天、MOQ 1000，
> 都来自结构化规格记录，不是模型编的。"

**关键一句**：
> "**报价必须人工签核、合同必须人工确认**——写操作和发送是分离的：
> Agent 只产出草稿，签核要带一次性闸门令牌。"

---

### 1:10–1:50 · 知识库：三个检索难点

**点**：左侧「知识库与检索」。

**说**：
> "这里演示跨语种召回：我在检索框里用**西语**问'FOB 价格和交期是多少'，
> 命中的是中文产品条目和中文规格记录——因为向量是多语种的，术语表把'plazo de entrega'和'lead time'对上了。
> 命中的每块都带'有效期'和'库版本'，法规和证书按**买家所在国 + 当前日期**过滤，
> 过期的不会出现在回答里。右边是 200 个概念的四语术语表，红字是**禁用译法**。"

---

### 1:50–2:15 · 看板：口径诚实

**点**：左侧「运营看板」。

**说**：
> "三张卡是上线门槛：引用正确率、名单召回、单位询盘成本。注意它们现在写的是**'待评测'**，
> 不是'已达标'——因为真实名单源没接、真实流量没有。分语种质量分层也是空的，
> 界面直接说明'暂无分语种评测数据'，并写明公开检索基准只做体检、不并入本表。"

**关键一句**：
> "**不把'没做'显示成'做得好'**——这个项目里最花时间的就是守这条。"

---

### 2:15–2:50 · 最有说服力的一段：它被证伪过

**说**：
> "这个项目不是写完就交。审核方**先于我实现**写定了 22 条判据，再用它测我的实现——
> 三轮下来共 11 个根因，我全部修完。举两个真问题：
> 第一，**双索引根本不成立**——块表主键只有 chunk_id，两个库版本的同名块会互相顶掉，
> 建新版本等于毁掉旧版本，回滚只能重建；改法是把主键改成 (chunk_id, kb_version)，
> 两个后端都写老库迁移。
> 第二，**试点企业被静默踢出灰度**——放量档按桶分流，白名单失效了，
> 台账上还写着这企业在灰度里，实际已经退回稳定版；这是"留痕说的 ≠ 做的"，最危险的一类 bug。"

**如果时间紧，只讲第二个**（业务影响更直观）。

---

### 2:50–3:00 · 边界与收尾

**说**：
> "边界我也说清楚：本期是**产品机制可验证的原型**，不是能上线的系统。
> PRD 13.4.12 的 12 行差距清单里 8 行未做；三条上线前置条件——真实名单源授权、
> 模型供应商条款、客户数据出境合规——不在开发范围内。
> 架构、验证口径、演示脚本都在仓库里，门禁是十三步全绿。谢谢。"

## 2. 如果只有 60 秒

1. **20 秒**：定位一句话 + 打开询盘工作台，指阿语那条草稿："自动应答，但报价要人工签核。"
2. **20 秒**：指右侧 11 条闸门 + 中间草稿下面的引用标签："每条结论能回指到证书编号/条目 ID。"
3. **20 秒**：打开看板的三张"待评测"卡："门槛没达标就写没达标，不粉饰。"
4. **加一句**："实现被一份先于实现写定的判据证伪过三轮，修了 11 个根因，仓库里有记录。"

## 3. 现场可跑的硬证据（比截图更有说服力）

在另一个终端窗口当场跑，让人看输出：

```powershell
# ① 交付门禁（十三步；双后端 + 独立审核）
& ".\dev.ps1" check

# ② 只跑 S6-3 独立审核（41 项 SQLite / 67 项双后端合计，30 秒内出结果）
& ".\dev.ps1" audit6r
```

**话术**："审核脚本不是我写的，是审核方按先写定的判据写的——我改的是实现，不是断言。"

## 4. 现场事故预案

| 事故 | 处置 |
| --- | --- |
| Docker 没起 / PG 连不上 | 前后端仍可用（默认 SQLite）；提前跑过一次 `dev.ps1 up` 即可 |
| 8080 被占用 | 换端口：`$env:TRADEDESK_PORT=8099` 后 `dev.ps1 serve`，前端地址同步改 |
| 界面空态、没有询盘 | 现场发一条（见第 0 节 curl 命令），10 秒出草稿 |
| 前端白屏 | 硬刷新；`config.js` 默认 mock 模式，双击 `ui-prototype/index.html` 也能演示 |
| 评委追问某个数字 | 打开 `docs/NEXT.md`（状态卡）与 `docs/S6-ACCEPTANCE.md`（验收基线），数字都有出处 |

## 5. 会被问到的问题（准备好答案）

| 追问 | 一句话答案 |
| --- | --- |
| 这跟阿里国际站的 AI 生意助手有什么区别？ | 人家比功能广度，我比**确定性**：草稿能不能直接给人签、名单命中拦不拦得住、回滚要不要重建、一条询盘能不能追责到底 |
| 为什么不自动签合同？ | 报价与合同是**商业承诺**，模型能起草但不能承担；所以写操作与发送分离，令牌一次性 |
| 怎么保证多语种不串？ | 多语种嵌入 + 术语表（含禁用译法）+ 查询扩展；证书/法规按买家所在国与当前日期过滤 |
| 名单召回怎么保证？ | 风控前置，命中即阻断不产生对外内容；召回率 ≥99% 是上线门槛，真实名单源接入后才适用（现在是模拟源） |
| 成本？ | 单位询盘 Token 成本 ≤ 0.2 元/条是硬指标；看板按**询盘条数**（不是调用次数）算，口径写在界面上 |
| 这个项目最大的不足？ | 生产化那一层基本没做；评测的询盘语料是自建缩减版；没有真实买家流量，所以门槛 10 顺延到 v1.1 |
