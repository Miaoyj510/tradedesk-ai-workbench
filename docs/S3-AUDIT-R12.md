## 二、违约项

### R12-01 · 正文里的证书行不按 `covers` 过滤 —— 别的型号的证书被说成覆盖本型号（P0，对外失真）

| | |
| --- | --- |
| 条款 | PRD 11.1「认证要求（Certification）：目的国产品认证要求、有效期、**覆盖型号**；回答必带证书编号」、PRD 9.3 引用装配、G-02 引用正确率 100%（硬指标） |
| 位置 | `src/tradedesk/agents/inquiry.py:204-213`（`cert_line` 取"命中列表里的第一张证书"） |

`cert_line` 从检索命中里捞证书，**只看命中顺序，不看这张证书覆不覆盖本型号**；
而同一文件里的 `_citations_from_hits`（`:250-253`）**是有 `covers` 过滤的**。
两套逻辑 → 正文与引用互相打架。实测（DE 买家问 M-77，消息里提到 CE 证书）：

```
正文：The model is covered by certificate CERT-CE-2041 (CE), valid until 2027-03-31.
引用：['M-77', 'CERT-ISO-9001', 'REG-EU-112', 'TERM-LEADTIME', 'TERM-MOQ']
```

`CERT-CE-2041` 的 `covers = ["X-200", "X-210"]`，**不覆盖 M-77**；引用列表正确地排除了它，
正文却把它说成覆盖本型号 —— **三语（en/es/ar）都复现**（断言 R12-01，3 组 × 2 项）。

这不是这次改出来的：main 上同样复现（R11 只查了"正文提到的证书在不在引用里"，
没查"这张证书覆不覆盖本型号"）。

最小改法：证书行按**产品的结构化字段** `extra.certificates` 取，
并用 `covers` 二次确认；`covers` 为空的证书（体系证书）走体系证书模板，
不说"型号被覆盖"（与 R11-10 一起做）。

### R12-02 · 证书被按买家国别过滤 —— 买家自己的产品证书被滤掉，由体系证书顶替（P0，对外失真）

| | |
| --- | --- |
| 条款 | PRD FR-KB-05（"**法规与名单条目**……按『买家所在国 + 当前日期』过滤"）、FR-KB-06（"规格参数走属性过滤，**证书与话术走语义召回**"）、FR-GRC-05、PRD 11.1 |
| 位置 | `src/tradedesk/retrieval/pipeline.py:92-109`（`filter_by_attributes` 对**所有** doc_type 生效） |

`CERT-CE-2041` 的 `countries = ["EU","DE","ES","FR","IT","NL","PT"]` —— 这是"证书适用法域"，
不是"买家国别专属的法规条款"。R11-01 的修法把国别过滤套到了**全部块**（含证书），
于是 BR 买家问 X-200 的 CE 认证时：

```
正文：The model is covered by certificate CERT-ISO-9001 (ISO 9001), valid until 2027-01-15.
引用：['X-200', 'REG-BR-077', 'CERT-ISO-9001', 'TERM-LEADTIME', 'TERM-MOQ']
```

X-200 真正的证书 `CERT-CE-2041` 被国别过滤掉了，**剩下体系证书顶替**，于是又踩中 R11-10。
（BR 买家不该拿到欧盟法规条款 REG-EU-112 这一点，修得对 —— 那是"法规"，按国别过滤没错。）

**要说清楚的是：问题不是"证书不能给非欧盟买家看"。** PRD 11.1 里认证要求确实按目的国落地，
但"这张证书覆盖 X-200"是**产品事实**，不该被买家国别滤掉；被滤掉之后由一张**不覆盖任何型号**
的体系证书顶位，才是失真的来源。

> main 上这个断言也红，但成因不同：那时证书没被国别滤掉，是"命中列表里的第一张证书"
> 恰好是体系证书。R11-01 的修法把证书也纳入国别过滤之后，成因变成了"产品自己的证书被滤掉"。
> 两者指向同一个修法：**证书按 `covers` 选，不按买家国别滤**。

最小改法：**国别过滤只作用于 `doc_type="法规条款"` 与 `"名单条目"`**；
证书按 `covers` + 型号过滤，不按买家国别过滤。
这同时回答了 R11 待定项 8：精确命中不放宽国别 —— 但**放宽的对象是法规条款，不是证书**。

### R12-03 · 国别未知时草稿仍按正常件外发（P1）

| | |
| --- | --- |
| 条款 | R11 报告 P1-3 的最小改法（"标为需人工确认（先问目的港所在国）"）、GATE-06、PRD 1293-1295 |
| 位置 | `src/tradedesk/agents/inquiry.py:254-262`（引用层的国别过滤）、`:184-185`（`needs_human` 只看置信度） |

引用层修对了（国别未知 → 一条国别专属法规都不进引用，断言 R12-03 第一项转绿）。
但**草稿状态没跟上**：

```
country="" → status=draft_ready  needs_human_confirmation=False  confidence=0.8
正文：Thank you for your enquiry about X-200. ... The model is covered by certificate CERT-CE-2041 ...
```

买家所在国未知，却按"合规要求已确认"的置信度（0.8）走正常签核流程。
PRD 1293-1295 的期望输出是"追问草稿：请问型号、数量、目的港、贸易术语" ——
正文里的 `ask_line` 确实问了目的港，但**没有把线程标成需人工确认**，
置信度与 GATE-06 的口径对不上。

最小改法：国别为空 → `needs_human_confirmation=True`（或把置信度压到阈值以下），
并在 `next_action` 里写明"先确认目的港所在国"。

## 三、记账项（不违约，但要记）

| # | 事项 | 说明 |
| --- | --- | --- |
| R12-04 | **属性过滤丢弃的块没有任何信号** | `RetrievalPipeline.filter()` 的 `dropped` 只装"已过期"的块；国别/HS 过滤掉的块直接消失。于是 agent 分不清"库里没有这个型号"与"这个型号被过滤掉了"，一律追问"请确认型号"。真因是"HS 编码库里没有对应产品"时，追问话术是错的。应把过滤原因带出来（计数或原因码）。 |
| R12-05 | **产品的 `extra.certificates` 无人消费** | 全项目 grep：只有 `kb_seed.py` 写、`inquiry.py:172` `setdefault` 读了一下就丢。"哪个型号有哪些证书"这个结构化事实躺在库里不用，证书行只能靠检索命中碰运气 —— R12-01 / R12-02 的放大器。 |
| R12-06 | **询盘链路没有 HS 编码输入** | `InquiryAgent._retrieve` 构造 `SearchQuery` 时只给 text / lang / buyer_country / today / top_k，**没有 hs_codes**。FR-KB-06"规格参数走属性过滤"在询盘侧目前是空的；检索层的 HS 过滤只被 `/kb/search` 用到（而该接口也没暴露 hs 参数）。 |

## 六、给实现 agent 的一句话

R11 的 8 个根因修掉了 5 个，方向都对；**"写死常量兜底"删得干净**（正文变成了
PRD 1295 要求的追问），**缓存改成内容指纹**也是对的解法。
剩下的问题集中在**证书这一条链路上**：检索层把证书当"别国法规"滤掉，
草稿层把命中的第一张证书当"本型号的证书"写进正文 —— 两处叠加，
就是对买家的合规声明失真。修这一组时记得 PRD FR-KB-06 的分工：
**规格参数走属性过滤，证书与话术走语义召回**。
