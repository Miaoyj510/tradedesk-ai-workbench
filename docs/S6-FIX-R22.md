## 二、修法（逐条）

### R22-01 索引版本独立成组件

- `release/manifest.py`：`COMPONENT_CATEGORY` 增加 `index_version` → 归 **knowledge 类**；
  `baseline_components()` 里索引版本默认随知识库版本。
- `release/service.py`：**换 `kb_version` 时索引版本默认跟着换**（块与向量必须同版本，
  否则新块没有对应索引，检索会掉到词法 + 结构化双通道）。
- 要单独把索引指向另一套**已建好**的索引，显式给 `index_version` 即可 —— 别名切换，不重建。
- **诚实边界**：本期"知识库类"回滚 = 块 + 术语表 + 索引**一起**切回；
  "只回索引不回块"需要按组件粒度的别名表，属生产化项。

### R22-02 / R22-03 白名单跨档位有效

- `release/bucketing.py`：`in_canary()` 改为
  **PILOT = 只认白名单；P20/P50/P100 = 白名单 ∪ 桶号 < 比例**。
- 理由：放量是"往里加更多人"，不是"把试点的人悄悄踢出去"。
  修完之后，发布记录里的灰度范围与实际命中集合一致（留痕说的 = 做的）。

### R22-04 / R22-05 / R22-06 越权闸门与审批人

- `api/auth.py`：角色能力表加 `release`（发布管理权）——
  **只有经理有**（`manager`），业务员 / 合规岗 / 管理层都没有；
  新增 `has_capability(user, capability)`（改角色表即改权限，不必改业务代码）。
- `api/app.py`：新增 `_release_guard()`，三个写端点（建发布 / 推进档位 / 回滚）统一走它：
  1. 鉴权开启时**审批人只能取自会话用户**（`username`）—— 请求体自称**一律不认**；
  2. 角色没有 `release` 能力 → **403**；没有会话 → **401**；
  3. 鉴权关闭（本地演示默认）时审批人仍须由请求体给出 ——
     宁可让人多写一个字段，也不给一个假的默认审批人。
- 审计留痕同步收紧：`release.create` 的 `actor` 与 `approver` 同源（都取会话用户）。
