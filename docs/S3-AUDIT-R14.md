## 二、违约项

### R14-01 · 同一张证书在引用列表里出现两次（P2，清单 1.11 必过条款）

| | |
| --- | --- |
| 条款 | 清单 1.11「命中不重复」、PRD 9.3 引用装配、G-02 引用正确率 100%（硬指标） |
| 位置 | `src/tradedesk/agents/inquiry.py:180-184` |

`_retrieve` 把按证书号回查到的证书**再 append 一次**进 `hits`：

```python
for cert_no in cert_nos:
    chunk = self._fetch_cert(str(cert_no), country, request.language.value)
    if chunk is not None:
        hits.append(SearchHit(chunk=chunk, score=1.0, channel="structured", ...))
```

而这张证书**本来就在原始检索命中里**（买家问 "CE certificate" 时词法命中了它）。
`_citations_from_hits` 逐条命中生成引用，不去重 → 同一张证书两条引用：

```
BR 买家问 X-200 + CE certificate
引用 = [X-200, CERT-CE-2041, REG-BR-077, CERT-ISO-9001, TERM-LEADTIME, CERT-CE-2041]
                                                        ^^^^^^^^^^^^^^^^^^^^^ 重复
```

M-77 那条没重复（证书没被词法命中），X-300 那条也没有 —— **是否重复取决于买家怎么问**，
这种"看情况"的缺陷最容易漏测。

最小改法：append 前按 `chunk_id` 去重（或在 `_citations_from_hits` 里按 `citation_id` 去重）。

### R14-02 · 报价里的三个数值没有可回指的来源（P1，引用正确率是硬指标）

| | |
| --- | --- |
| 条款 | FR-KB-07「每条检索结果必须携带可回指标识：……**产品 SKU 与规格版本**」、PRD 9.3 引用装配、VP-08 / G-02「每条结论可回指，引用正确率 100%」 |
| 位置 | `src/tradedesk/agents/inquiry.py:180-185`（`_fetch_spec` 的结果没有进 `hits`）、`:346`（引用只取 `产品条目` 的 sku） |

R13 把数值搬进了 `产品规格` 块（这是对的），但**那块没有进引用列表**：

```
正文：Our reference price for 1000 pcs is USD 4.85–5.2 ... lead time of 25-30 days
引用：['X-200', 'TERM-LEADTIME', 'TERM-MOQ', 'REG-EU-112', 'CERT-CE-2041']
      ^ 指向的是**描述性文本块**（title = "X-200 Manual Hydraulic Hand Truck"），里面没有价格
```

价格、MOQ、交期是正文里最硬的三条结论，**没有一条引用指向它们的来源块**；
规格版本（`attr_id=SPEC-X-200`）也不在引用里 —— FR-KB-07 要的是"SKU **与规格版本**"。
签核人点开 "X-200" 这条引用，看到的是一段描述性文字，看不到 4.85 这个数从哪来。

最小改法：把 `产品规格` 块作为一条引用（`citation_id` 用 `SPEC-<sku>` 或规格版本号），
并让产品引用带上 doc_id + 语言标签（见 R14-03）。

### R14-03 · 引用定位不到具体块：一个 sku 现在对应 5 个块（P2）

| | |
| --- | --- |
| 条款 | FR-KB-07（产品 SKU **与规格版本**）、PRD 9.3 引用装配「每个块携带 `doc_id + …… + 语言标签`」 |
| 位置 | `src/tradedesk/agents/inquiry.py:346`（`citation_id=c.identifiers.get("sku", ...)`） |

R13 之后一个型号有 5 个块（4 语 + 1 规格），但引用的 `citation_id` 仍然只是 sku：

```
sku=X-200 → ['KB-A-SPEC-X-200', 'KB-P-X-200-ar', 'KB-P-X-200-en', 'KB-P-X-200-es', 'KB-P-X-200-zh']
```

引用 "X-200" **指不到具体块**。note 里只有标题和库版本，没有 doc_id、没有语言标签、
没有规格版本 —— 签核界面与将来的前端拿到这条引用，没法定位到"是哪个语言的哪一版规格"。

最小改法：产品引用带 `doc_id`（如 `SKU-X-200-en`）+ 语言标签 + 规格版本；
或引用 id 用 `sku@lang@规格版本` 这类可定位的复合标识。

## 三、记账项（不违约，但要记）

| # | 事项 | 说明 |
| --- | --- | --- |
| R14-04 | **词法通道跨型号噪声**：查 X-200 时，X-300 的两个块进了前 5 | 数字 bigram 撞车（"200" 与 "300" 共享 "00"）。分数差得多（0.093 vs 0.015），排序上无害；但 S4 加了向量通道后要复测这条。 |
| R14-05 | **规格回查靠 `top_k=5`，与"同型号块数"耦合** | `_fetch_spec` 用 `search(text=sku, top_k=5)` 再按 sku 过滤。现在恰好能取到（规格块排第 1），但同型号块一多（加别名块、加第 5 种语言），规格块可能掉出前 5 → `_fetch_spec` 返回 None → 报价报不出来（安全降级为追问，但"该报价报不出来"）。建议改成精确查询或放大 top_k。 |
| R14-06 | **体系证书会作为型号的"证据"出现在引用里** | X-200 的引用里有 `CERT-ISO-9001`（`covers=[]`），正文没提它。签核人容易读成"X-200 的证书"。建议 `covers` 为空的证书不进型号证据列表，或在引用 note 里标明是工厂体系证书。 |
| R14-07 | **证书 / 法规 / 术语块仍是单语（zh）** | PRD 9.1 把这些列为中文源知识，不算违约；但 S4 的语种分层评测里，"买家问认证"这条线的语义通道只有中文文本可召回。 |
| R14-08 | **`产品规格` 块的文本是模板句** | "X-200 的规格以结构化属性存放：材质、载荷、起订量……" —— 三个 SKU 高度相似、语义上无信息量。建议 S4 把 `产品规格` 块**排除在语义通道之外**（它只走属性过滤），否则会成为向量库里的噪声。 |
| R14-09 | 产品文本块的 tags 里还有 `MOQ` / `lead time` / 港口 | tags 进 BM25 文档（与正文同权重）。不是数值，不违反 PRD 9.3；但 S4 若把 tags 拼进嵌入文本，属性词又会回到语义通道，建议 S4 明确 tags 与文本的边界。 |

4. **R14-04 / R14-06 ~ R14-09**（记账）—— S4 做向量通道时一并处理：
   语种分层的评测集、语义通道的块白名单、tags 与文本的边界，都在 S4 一次定清楚。

## 六、给实现 agent 的一句话

R11/R12 的 11 个根因**修得干净**：写死兜底删了，缓存按指纹失效，数据模型按 PRD 9.3
重做成"一份结构化规格 + 四份语言文本"，证书口径也按 covers 收紧了 —— 这几处的取舍
（数值只存一份、体系证书换模板、国别过滤只管法规条款）都是对的。

引用还停留在"sku + 标题"的旧口径 —— 于是同一张证书引两次、价格的来源块没被引用、
引用指不到具体块。这三个一起改，改完 `dev.ps1 check` 的第七步就会绿。
